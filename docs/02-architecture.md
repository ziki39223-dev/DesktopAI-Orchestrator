# 架构说明（Architecture）

> 状态：Phase 0 · 仅完成 L0 分层概览。L1–L4 分层图按需逐层补（见 `00-doc-map.md` §2），本文件每轮只追加一层。

## 1. 一句话架构

上层编排器通过 MCP 协议（SSE / stdio）调用本项目；本项目内部经“工具路由层”在 **Mock 后端** 与 **UIA 真机后端** 之间切换，真机后端再用 Windows 原生 UIA + 窗口捕获去操控三款 Electron 客户端。

## 2. L0：分层与依赖方向

```
┌──────────────────────────────────────────────────────────────┐
│ 上层编排层（本项目之外，可换）                                │

│   职责：任务拆解、流转判断、结果汇总；不做识图                 │
└───────────────────────────┬──────────────────────────────────┘
                            │ MCP 协议：SSE（主推） / stdio
┌───────────────────────────▼──────────────────────────────────┐

│                                                              │
│  ┌ 传输层 entry/ ────────────────────────────────────────┐    │
│  │  SSE 服务入口            │  stdio 子进程入口           │    │
│  └──────────────────────────┬────────────────────────────┘    │
│  ┌ 服务装配 server/ ────────▼────────────────────────────┐    │
│  │  MCP Server 实例、能力注册、生命周期                    │    │
│  └──────────────────────────┬────────────────────────────┘    │
│  ┌ 工具层 tools/ ───────────▼────────────────────────────┐    │
│  │  list_target_windows / send_prompt /                  │    │

│  │  只做：入参校验 → 调后端 → 出参封装 → 错误映射          │    │
│  └──────────────────────────┬────────────────────────────┘    │
│  ┌ 契约层 contracts/ ────────┤ 唯一真源，冻结后不改          │    │

│  ┌ mock 后端 ▼ ┐              ┌ real 后端 ▼ ──────────────┐    │
│  │ 无 GUI 依赖  │              │ 窗口枚举 / 画面捕获 /      │    │
```

依赖方向（硬规则，违反即打回）：
`entry → server → tools → routers → backends`；`contracts` / `config` / `common` / `observability` 是被依赖方，**任何层都不得反向 import 上层**，`backends` 不得 import `tools`。

## 3. 运行模式矩阵

| 维度 | Mock（开发机） | Real（工作机） |
| --- | --- | --- |
| 传输 | SSE / stdio 均可 | SSE / stdio 均可 |
| GUI 依赖 | 零；Windows 专属库延迟导入且不触发 | 需要 UIA + 捕获库 |
| 窗口来源 | `window_rules.json` 中的静态清单伪造句柄 | 真实 `EnumWindows` 匹配 |
| 输出内容 | 脚本化文本 + 结束标记，可配置延迟与失败注入 | 真实聊天区文本 |
| 用途 | 契约、编排流程、CI | 生产 |

## 4. 关键设计取舍（详见 `07-decision-log.md`）

1. **工具层零业务**：所有“怎么做”都在后端，工具层只做契约边界，保证换后端不改工具。
2. **契约先行冻结**：`contracts/` 是唯一真源，编排侧对着契约开发，MCP 服务可独立演进内部实现。
3. **规则外置**：Electron 控件路径不写死代码，全部进 `window_rules.json`，支持 `reload_window_rules` 热重载。
4. **未完成不是错误**：`fetch_output` 用状态字段表达“还在生成”，超时/未完成与异常分离，编排器据此循环。
5. **不做识图**：成本控制；画面捕获仅作降级与取证，不进主判定链。
6. **单进程单后端**：一期不做多客户端并发调度，先保证单窗口串行可靠（并发留作后续扩展点）。
